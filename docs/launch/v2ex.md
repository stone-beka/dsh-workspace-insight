**正文**：

DSH（DeepSeek Harness）用久了会遇到一个很具体的问题：侧栏只显示每个工作区的最近状态，但你可能有几十个工作区、几百条会话。

于是就有了三个问题：

- 哪些工作区我还在用，哪些已经三个月没碰了？
- 某个项目我到底哪几天在推进？
- 这些会话里哪些可以放心归档？

我写了个插件 `dsh-workspace-insight` 来回答这三个问题。它只读本地数据，不发任何网络请求。

## 三个视图

**总览**：一行一个工作区，列出最近使用时间、会话数、轮次、模型+工具耗时、近 14 天触达柱。超过 20 天没动但还挂着会话的工作区会自动标「建议归档」。点开一行能看到具体会话，可直接打开 / 归档 / 取消归档。

**月视图**：日历。每天格子里按「当天各工作区的会话数」**按比例左右分格**，每格用该工作区的固定色，段内竖排写工作区名——所以一眼能看出「这天主要是哪个项目在推进」。上方有月度摘要：活跃天数、对话数、涉及工作区、最长连续活跃、环比上月。

**时间轴**：行是**连续日期**（一天不落），列是工作区（固定色，按活跃度分 7/14/21 天三段），周与周之间虚线、月份实线。每格列出当天用过的对话，悬停看全名，点击直达会话。支持选列、展开全部、Ctrl+滚轮连续缩放；滚轮上下、左键拖动平移。

**归档是真诚做实事的**：所有归档动作走的都是 DSH 自己的 `uiWorkspace` 服务，不是插件自己写存储。

## 技术上的取舍

- 数据全部来自 `$DSH_HOME`：注册表、会话投影缓存、会话日志（多帧 zstd，逐帧解压提事件时间戳做日索引）。
- 日索引按文件 `size+mtime` 增量缓存，首次扫描 5–10 秒，之后 100–300ms；扫描每 40 个文件让出一次事件循环，不阻塞 Host。
- 存储格式做了探测：注册表/投影缓存缺失、日志版本不认识时给警告条而不是乱算。
- 无构建步骤，Host/Client 各一个文件，MIT。

## 安装

```
dsh plugin --profile web add dsh-workspace-insight
```

装完硬刷新页面，左侧栏出现柱状图图标，点它切到「工作区洞察」。

## 已知限制（先说清楚）

- 只统计有投影缓存的会话；
- 单位是「会话-天」，不是消息条数；
- 耗时是本地计时，不是计费口径；
- 直接读宿主的内部存储，DSH 大版本改格式需要跟进适配（会先给警告，不会给错数）。
