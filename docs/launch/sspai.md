# 少数派 / 知乎 长文版

**标题**：把 DSH 的会话历史变成一张地图：工作区洞察插件是怎么做出来的

**导语**：

> 当 AI 工作台里的「会话」多到几百条、工作区多到几十个，你需要的不是更长的侧栏，而是一张能回答「我最近在忙什么、哪些可以收掉」的地图。

---

## 一、问题不是「记录不够」，是「视角不对」

DSH 会保存每一条会话，但侧栏只展示每个工作区的最近状态。于是日常出现三种尴尬：

1. 想清理工作区，却记不清哪个还在用；
2. 想知道某周在推进什么，只能一个个点开对话；
3. 想归档，又怕把还在用的东西收起来。

我自己的情况：【39 个工作区、400 多条会话、从 8 月到现在】。于是做了 `dsh-workspace-insight`。

## 二、三个视图，对应三种问题

### 总览：哪些工作区还活着

一行一个工作区：最近使用时间、会话数、轮次、模型+工具耗时、近 14 天触达柱状图。20 天没动但仍有会话的会标「建议归档」。展开就能看到具体对话并直接归档——归档调用的是 DSH 自己的 `uiWorkspace` 服务，不自己写存储。

### 月视图：这个月我在干什么

日历里每天一格，**格内按当天各工作区的会话数左右按比例分块**，每块用该工作区的固定颜色，块内竖排写名字。于是「这天主要在做哪个项目」不需要读文字，看色块比例就知道。上方是月度摘要：活跃天数、对话数、涉及工作区、最长连续活跃、环比上月。

### 时间轴：长期趋势

行是**连续日期**（不跳过空白天），列是工作区（固定色，按最近活跃分 7/14/21 天三段），周与周之间虚线分隔、月份首日实线。每格列出当天对话，悬停看全名、点击直达。支持选列、全部展开、连续缩放。

## 三、三个设计决定

**1）只读，不碰存储。**
数据全部来自 `$DSH_HOME` 的本地文件，插件不写入任何会话或工作区状态；归档一律走宿主服务。这样最坏情况是「显示不对」，而不是「数据被改坏」。

**2）读取内部存储，但做格式守卫。**
日活跃索引来自会话日志（多帧 zstd，逐帧解压提取事件时间戳）。这条路依赖宿主内部格式，所以我加了探测：注册表/投影缓存缺失、日志版本不认识时给警告条，而不是算出错误数字。验证时真发现 39 个 v3 老日志，顺手做了兼容。

**3）扫描不能卡住界面。**
首次扫描 200MB 日志约 5–10 秒。做法是分批异步（每 40 个文件让出事件循环）+ 按 `size+mtime` 增量缓存，第二次 100–300ms。

## 四、怎么用

```
dsh plugin --profile web add dsh-workspace-insight
```

装完硬刷新，左侧栏出现柱状图图标；设置页也能打开。MIT 开源，仓库与 npm 都在下面。

## 五、边界（先说清楚）

- 只统计有投影缓存的会话；
- 统计单位是「会话-天」，不是消息条数；
- 耗时是本地计时，不是账单；
- 直接读内部存储，DSH 大版本改动需要跟进（会先警告）。
