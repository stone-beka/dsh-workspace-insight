# 发布素材（中文）

> 这个目录是发布用的文案草稿，不参与插件运行。发之前请把 `【】` 里的占位内容换成你的实际情况，并补上截图。

## 需要你补的东西

1. **截图 3 张**（放 `docs/launch/img/`）：
   - `overview.png` — 总览（能看出多个工作区 + 建议归档徽标）
   - `month.png` — 月视图（能看出格子里按工作区比例分色 + 竖排名字）
   - `timeline.png` — 时间轴（能看出连续日期 + 列色 + 周分隔线）
2. **真实数字**（帖子里的示例数据是参考值，按你机器的实际情况改）：
   - 工作区数、会话数、时间跨度（例如「39 个工作区、400+ 会话、84 天」）
3. **一句你自己的感受**：为什么做这个、之前被什么烦到。

## 发布顺序建议

1. 先发 GitHub Release（已完成 `v0.2.0`），确认 npm 页面能打开
2. 提交插件目录（`dshfind.md`）
3. 发 V2EX（技术受众，能引 issue）
4. 发即刻 + B 站（传播）
5. 少数派/知乎放最后（沉淀长文，需要截图齐全）

## 统一事实（发布时保持口径一致）

- 包名：`dsh-workspace-insight`
- 安装：`dsh plugin --profile web add dsh-workspace-insight`，装完硬刷新
- 仓库：https://github.com/stone-beka/dsh-workspace-insight
- npm：https://www.npmjs.com/package/dsh-workspace-insight
- 许可：MIT
- 兼容：DSH Web profile，在 `0.2.2-rc.1` 验证；Host 端需要 Node ≥ 20
- 数据：只读 `$DSH_HOME` 本地文件，不发任何网络请求
- 局限：只统计有投影缓存的会话；单位是「会话-天」；耗时是本地计时

## 截图怎么截

1. 左侧栏点柱状图图标，切到「工作区洞察」
2. 窗口拉到最大（三列都撑开），深色/浅色都用当前主题即可
3. 分别截：
   - 总览：默认页，行数能露出 15+ 工作区、最好有一两个「建议归档」徽标
   - 月视图：选一个有数据的热闹月份，能看出格子里分色和竖排名字
   - 时间轴：默认缩放，能看出连续日期、列色、周虚线
4. 存成 PNG 放进 `img/`：`overview.png`、`month.png`、`timeline.png`
5. 想录 GIF：从「点开图标」到「切一次月视图/时间轴」，10 秒左右即可
